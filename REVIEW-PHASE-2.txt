REVIEW NOTES (things a reviewer should know going in)
-----------------------------------------------------
1. #171 vs #172: #171 as merged is INCOMPLETE. A stash accident
   silently reverted its proto rename and the mapping-pipeline sweep
   before the final push, leaving main briefly with BOTH java records
   (ChunkRecipe still wired into the mapping pipeline, ChunkingPolicy
   wired into the chunker). #172 completes the rename for real,
   including the wire (deliberate pre-GA break: message ChunkRecipe ->
   ChunkingPolicy, field chunk_recipe -> chunking_policy, tag 21
   unchanged). Review them as a pair.

2. buf breaking waivers: path-based breaking.ignore NEVER matches in
   this multi-module v2 workspace (proven empirically on buf 1.70 with
   a real wire break present; tried current side, against side,
   module-relative paths, --exclude-path). #170's waiver was inert and
   #171 passed CI only because its wire break was missing. What works:
   a rule-level `breaking.except` block naming the tripped rule IDs,
   carried IN the breaking PR itself (buf reads breaking config from
   the input side), dropped in the next PR. buf.yaml keeps a standing
   note. While an except block exists it is workspace-wide, so a
   breaking PR's proto diff must touch only the intended files
   (verify: git diff main --stat -- '*.proto').

3. Body fold gap (found by the door, fixed in #174): the coordinator's
   fold accepted a `body` claim that NO parser ever made, so indexed
   documents had no searchable text; the golden path had been papering
   over it with a fallback. The reference text parser now claims body
   (the non-title text blocks). Worth a look: is this the right
   long-term source of body text for non-text parsers (gRParse et al.)?

4. Previews are forwarded, not requested: gRParse's streaming wire
   (DocumentChunk) carries no processing options, so the adapter cannot
   ask for page renders. It forwards them when the fleet is built to
   produce them; emits_previews is therefore deployment config, not a
   detected capability. PreviewSpec parameters are ignored (the plugin
   contract allows this). If the fleet later accepts options on the
   stream, the adapter should start honoring PreviewSpec.

5. Known CI flake: WorkflowWorkbenchMcpTest in apps/serve (hit #175
   build 25, and two unrelated PRs before that). Unrelated to this
   train; owned by the serve track.

6. Stale-branch gotcha (bit #175): a PR opened before a proto-adding PR
   merges will fail buf breaking on RERUN with "message deleted",
   because the rerun re-fetches a moved origin/main. Rebase onto fresh
   main and push; never just rerun.

HOW TO SUBMIT REVIEW CHANGES
----------------------------
- Main is PR-only (GitHub is a live mirror of canonical Forgejo
  git.rokkon.com). Branch off fresh main, open a PR; either
  findings-as-comments on the merged PRs first, or a direct fix PR
  whose diff carries the conversation.
- Real merge commits only (no squash/rebase merges). Push Forgejo
  first, then GitHub. No em dashes in commit messages, no AI
  attribution footers, no hand-cut v* tags.
- Rebase onto fresh main immediately before opening the PR (see note
  6); main moved 13 PRs in one day during this train.
- Wire breaks are still sanctioned pre-GA (nothing in production), but
  carry a breaking.except block per note 2.
