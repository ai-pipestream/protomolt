# Goal 1 reconciliation: apps and execution families

Read-only source audit on 2026-09-24 in `feat/starter-contracts`. This covers the
`apps`, `host`, `surface`, `core`, `transform`, `mesh`, `jobs`, and `inference`
families. The sibling inventory covers other domain trees. “Source/test” below
means code and test cases inspected, **not a fresh test pass**. No build, live
provider, browser, deployment, or recovery run was performed for this audit.
Existing Goal 1 fixture results are recorded separately in
[`starter-contract-verification.md`](starter-contract-verification.md).

The two candidate app entry points are real but differently scoped. `apps/serve`
builds `ProtoMoltCatalog.full`, mounts gRPC, REST, MCP, registry and console,
and conditionally adds Git-backed workflows, filesystem artifact/run storage,
JDBC jobs, inference, durable delegation, and mesh. `apps/document-platform`
explicitly feeds role modules to `Composer`, with local or
`PROTOMOLT_<ROLE>_TARGET` channels; its default roles include repo, registry,
parse, jobs, intake, search, metric and their consoles. It is **not** a host for
the serve task console or correction workbench. Its Compose deployment supplies
Postgres, RustFS and the role node, but requires `:protomolt-document-platform:installDist`
before `docker compose up --build`. Neither path is a proven clean-install
starter. Compare a small `serve` path and a role-node path against the same
first-result and recovery cases before selecting an app default. Do not make
the entire document platform a correction prerequisite.

## Contract and backlog consequence

No additional Goal 1 wire message or RPC is required by this audit. The existing
`WorkflowDeliverable`, `EvaluationBinding`, workflow and delegation envelopes can
name the work; new behavior belongs in handlers, policy, packaging and tests.
Before Goal 2 handlers or a Goal 3/4 app default, add these explicit backlog
cases to the existing CORE/ENTRY/REVIEW work:

1. **ENTRY-PACKAGE:** clean install starts a named correction with a pinned
   descriptor closure, configured Git workflow registry, artifact/run store,
   and optional JDBC jobs. Record setup steps and time to first **recorded**
   result. Test restart separately from `--demo` temporary directories. Compare
   `serve` and document-platform role node with the same acceptance case and
   document which process owns each store and exposed route.
2. **COORD-RECOVER:** for accept-without-candidate, missing worker follow-up,
   lease expiry, checkpoint re-offer, process restart and pending local command,
   expose reason, next actor, bounded retry/escalation and stable task/attempt/
   revision. A requested objective/scope/check revision must invalidate stale
   candidate/evaluation/review evidence. Human approval never arises from expiry.
3. **ENTRY-TRANSPORT:** exercise the same invalid nested request and malformed
   successful evaluator response across mounted gRPC/MCP/ACP/REST paths, plus
   token-mode console behavior. A generated descriptor or a UI control is not
   proof of a callable/validated operation.
4. **CORE-EVIDENCE:** pin registry schema/workflow and service-profile artifacts;
   distinguish correction validation from semantic support and unresolved
   declaration. Store exact run/attempt evidence before signing or evaluation.

These are Goal 2+ implementation and acceptance items. The new evaluator still
needs its specified request/response, digest, authority, retry and freshness
gates when a handler is implemented. Do not silently substitute the existing
`EvaluateWorkRecord` action or a provider-specific adapter for that service.

## Limits and website cross-check

`docs/website-feature-inventory.md` is a useful index, not runtime proof. Its
“shipped” label includes test-backed libraries, configured services and demos;
the exact mounted path and prerequisites above control starter claims. In
particular, the court corpus figure in its proposed marketing sentence does
not mean 9.7 million opinions passed the metadata-filling workflow. The saved
court QA rounds contain 315 document/persona result records, as the existing
inventory explains. `mesh.v1` options have no broad runtime reader, OpenAPI
does not enforce all validation annotations, service-profile credentials are
currently refused at call time, and the evaluation proto is contract-only.
S3-compatible repository storage exists, but the `serve` delegation and mesh
paths use it only through configured repository service endpoints and keys.

Coverage includes every module family in the assigned eight trees, grouped by
capability rather than class. Deeper tracing was concentrated on the two app
entry points, stores, routing, coordination, jobs, inference and validation
surfaces. This audit did not inspect every alternate server adapter or every
format/mapping algorithm, and it did not verify current live NAS containers,
provider sessions, hosted CI, or the external historical court harness.
